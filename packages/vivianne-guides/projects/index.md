# Projects

An agent does good work on a project only when it knows the project: what it is for, who it serves, how it is built, what has been decided and why, and where it is going. These guides are how Vivianne (or any agent) gets that knowledge, keeps it current, and works from it.

| Guide | When |
|---|---|
| [new-project](new-project.md) | A project is starting from nothing. |
| [existing-project](existing-project.md) | Joining a project that already exists: a codebase, a document set, a running business. |
| [knowledge](knowledge.md) | The project's living knowledge: which files, what goes in each, how to keep them true. |
| [working](working.md) | How to do each piece of work so it moves the project forward and leaves it easier for the next agent. |
| [roadmap](roadmap.md) | Objectives, milestones and what's next: keeping the future written down. |
| [team](team.md) | When several agents work on one project: lead, specialists, handoffs. |

## The short version

1. **Know before you act.** Read the project's knowledge files (`.viv/charter.md`, `.viv/map.md`, `.viv/roadmap.md`, `.viv/journal.md`) before any non-trivial task. If they don't exist, create them first.
2. **Verify, don't assume.** Knowledge files can be stale. Check what matters against the real project (the code, the files, a command's output) before relying on it.
3. **Write it down as you go.** Decisions with their reasons, new conventions, changed plans. What isn't written down gets contradicted by the next session.
4. **Leave it better.** End each task with the knowledge files updated and a short journal entry: what changed, what's next, what's uncertain.
