# Roadmap

The roadmap keeps the future written down, so every task can be measured against where the project is going.

## `.viv/roadmap.md`

```markdown
# Roadmap

## Objectives
- <Outcome, measurable> — by <when>
- …

## Now — <milestone name>
Done when: <concrete definition of done>.
- [x] Task — note
- [ ] Task
- [ ] Task

## Next
1. <Milestone> — <why it's next; done when …>
2. …

## Later
- Ideas and wishes, unordered. Not commitments.

## Done
- <Milestone> — <date> — <what shipped, one line>
```

## Rules

- **Objectives are outcomes**, not features: "half of new users invite a teammate in week one", not "build invites".
- **Milestones are shippable**: each ends with something working that a person can use or see.
- **Every milestone has a definition of done** you can check.
- **Only one "Now".** If two things are in progress, one of them is really "Next".
- **Re-plan when reality changes** — a decision, a discovery, a new request — and say in the journal why the plan moved.
- **The user owns priorities.** Propose changes to the order; don't reorder silently.
- When a request doesn't fit any objective, ask whether it's a new objective, part of an existing one, or a one-off.
